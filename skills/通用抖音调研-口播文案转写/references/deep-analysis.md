# 原文提取与保存

## 本阶段唯一默认目标

把选定视频实际说出的口播完整提取下来，供下一步AI改写使用。只处理选中视频，不重新行业搜索，不先写自家脚本。

```text
请使用“通用抖音调研”Skill，提取口播原文。

视频链接：【抖音视频链接】
自己的产品：【产品或服务】
提取目的：保留参考原文，供下一步AI改写使用。
交付方式：只提取视频实际说出的内容，不改写、不增删，补充到本客户原有多维表格的对应视频记录，返回表格链接。
```

产品信息不是替换指令。参考里说的价格、品牌、杯子数量仍按参考原话保留；不得改成自己的卖点。需要镜头快拆时，另行提出并单独保存，不能插入原文正文。

复核视频身份与总时长，默认上限90秒。复用同一视频已有的完整字幕、原始ASR、媒体和任务ID；先检查其视频对应关系与完整区间。完整原文已存在就直接使用，不为了演示再下载或重复提交ASR。搜索snippet、发布文案或零散屏幕字不是完整口播。

## 原文的保真边界

默认交付“转写原稿（未改写）”。保留重复、语气词、顺序和原有表达。机器识别稿必须保留原始结果；未经逐字听校，不声称字字无误。确认识别错误时，只按原音校正并另记校对记录；不能凭产品常识改词。无法听清的疑点放在正文外单独备注，不擅自补句。

## 需要ASR时

1. 在下载前确认当前宿主有下载与转写能力，所用服务授权可用；不要求第一阶段提前安装这些依赖。没有能力就说明能提取到哪一步，保留来源，不假装已转写。
2. 优先使用宿主支持的视频下载工具。先读当前浏览器文档；若播放器JS方法已在本任务报错，不重复同一调用。允许使用文档支持的页面网络观察：本次豆包实测可在同一调用内导航目标视频、等待媒体加载、以 `bu.network_requests()` 获取当前媒体请求并立即 `bu.download()`，将已取得的完整URL保存在该调用变量中；不要跨调用重复消费可能已清空的网络缓冲。仅取当前目标视频实际产生的媒体请求，不重放隐藏接口、不输出带签名媒体直链。旧豆包浏览器曾可读取当前播放器的 `currentSrc`（为空再检查 `src`）；使用前核验视频身份与工具权限。`blob:`、网页URL不是可直接交给远端ASR的媒体文件。不硬编码作者电脑路径、不猜下载目录，使用下载返回的实际路径并检查文件存在且非空。URL失效允许重新获取一次，不无限重试。
3. 转写接口先看当前工具文档。若环境有 `mediakit-cli`，先检查其帮助，确认本版本接受本地路径及相应参数后才使用旧版命令形态：

   ```text
   mediakit-cli video asr-subtitles --video-url <实际媒体路径或受支持URL> --language cmn-Hans-CN
   mediakit-cli shared query-task --task-id <返回的任务ID>
   ```

   根据实际音频语言设置识别语言；中文材料使用简体中文。不能假定本地路径一定被CLI自动上传。参数按当前shell正确引用，不把用户内容拼成可执行代码。
4. 提交后立刻记录任务ID、视频ID、输入路径和状态。默认总等待上限180秒、每15–30秒查询一次；单次调用也设置可用的超时，不使用无界 `--poll-complete`。达到总上限即交付已完成部分和续跑信息，不再提交同视频任务。用户继续时先查询原任务；失败原因明确且修正后才考虑重新提交。
5. 保存工具原始返回JSON（包括任务ID、每段原始时间戳和文字），另生成逐段字幕文件与纯文本稿。逐段稿与原始返回逐条核对，不手工合并时间段制造重叠；原始工具若自带重叠则保留并标注，不能静默改时间。纯文本稿只顺序拼接实际识别内容，称“完整ASR稿”，未经逐字听校不称人工核准原话。仅依据上下文和音频核对明显误识别，品牌名、数字、否定词拿不准就标疑点；不套固定品牌替换表。无结果或极短文本只能说明识别不足；确认实际没有人声才能标“无口播”。分别标注视频总时长和可确认的语音区间，不把两者混为一谈。
6. 若需要清理，仅在结果已交付/保存且无续跑需要后，按当前授权删除本任务新建的临时媒体；失败、待续跑和用户原始文件保留，说明位置。禁止通配符清理下载目录或其他任务文件。

## 保存到原多维表格并验收

按 [多维表格持续保存](feishu-save.md) 定位当前客户的表和视频记录，保留原版字段与视图。将完整转写写入“口播文案”，只补本阶段字段，原话正文不混入说明、推荐理由、镜头、自家改写或分析。原文来源与校对状态写“备注”，保留已有备注；未指定位置时优先复用客户绑定，不另建文档。

写后回读“口播文案”，与纯文本原稿逐字比较，核对无截断、无摘要、无额外加词。交付表链接和记录定位；远端不可访问则保留待写入数据并说明未保存，不把本地完成说成飞书完成。用户明确另要文档时才额外创建，重试复用已有文档。

## 从原始ASR确定性导出

当原始结果是本次已验证的mediakit结构（`status=completed`、`subtitles`列表，含`start_time/end_time/subtitle_text`）时，运行 [ASR导出器](../scripts/render_asr.py)：

```text
python3 <本Skill目录>/scripts/render_asr.py <原始JSON路径> --output-dir <本任务交付目录>
```

输出 `asr-verbatim.txt`（仅按段换行，不加标点）、`asr-segments.srt`、`asr-segments.md` 和 `asr-integrity.json`，并自动回读。需要时在记录备注中注明可访问的导出文件，不再手抄一份字幕时间表。需要添加标点或纠错的阅读稿另存并标“整理版”，不可覆盖机器原稿。结构不同先按实际工具返回适配，不猜字段；无Python时按相同原则逐段保留并说明未运行导出器。
