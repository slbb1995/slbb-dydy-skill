# 持续保存到同一张飞书多维表格

默认自动落表：第一阶段保存已核验的参考；第二阶段把完整口播原文补回同一行。以后继续调研追加新记录，不每次新建表或独立文档。用户明确要求只在对话交付、不保存或另存文档时遵从。

## 定位与记住目标（包括完全新对话）

客户身份沿用企业资料或对话中明确的企业名称；缺少且会导致混写时只问客户名称。相同客户使用稳定名称；别把每次调研主题作为新客户。用户提供明确表链接时优先使用，变更已绑定目标需符合其指令。

每次开始保存流程时（继续调研则在搜索前），按顺序定位：

1. **固定跨对话入口**：运行随包脚本，不搜索全电脑：
   ```text
   python3 <本Skill目录>/scripts/base_binding.py get --client "客户名称"
   ```
   默认读本机用户目录 `~/.local/share/slbb-dydy/bindings/`。这是客户运行数据，不在Skill安装目录，也不随ZIP分发。不同客户独立文件，Codex、WorkBuddy和豆包本机任务可从同一路径读到。同一客户如有多个独立项目，使用明确的“客户名/项目名”，不能擅自拆分。
2. **核验再用**：命中后用当前飞书登录身份读取Base和目标表，确认客户归属和实际字段。已有绑定无权限/失效时保留绑定并报告，不另建替代表。已找到目标就停止其他定位步骤。
3. **没有固定绑定时恢复旧表**：先检查当前项目 `douyin-research/base-binding.json` 和宿主旧 `.base-memory.json` 候选；本地候选不属于当前客户则排除，不据此提前询问或新建；没有匹配时按“客户名称＋抖音调研”在飞书中检索已有多维表格，结合表名、表字段和少量记录核对归属。单一匹配则复用，不因本地没有绑定就新建表；多候选/归属混杂只问一次。不要遍历整个家目录、所有旧聊天、Obsidian或其他无关仓库。远端搜索无权限或未完成不是“没有表”。
4. **确认首次才建表**：没有已绑定/指定目标，且远端检索完成未找到当前客户调研表时，在该客户飞书空间创建 `客户名｜抖音调研结果-口播文案版`，表名 `调研记录`。按 [原版25字段](base-schema.json) 一次建字段，首字段“视频标题”为主字段；记录返回坐标后再补8类视图，失败按坐标续建而非重复建Base。
5. **找到或创建后立即登记**：核对真实链接与table_id后运行（任何客户都执行，不只测试客户）：
   ```text
   python3 <本Skill目录>/scripts/base_binding.py register --client "客户名称" --base-token "实际Base标识" --table-id "实际数据表ID" --url "实际表格链接"
   ```
   脚本会写入并回读跨对话绑定。另可在项目中保留 `douyin-research/base-binding.json`，但不能只保存到本次新聊天目录。不同表的绑定冲突不能直接覆盖；只有用户明确切换表时使用 `--replace`。

脚本不创建或修改远端表，也不替代飞书权限/客户归属核对。不同客户默认分别绑定，用户明确合用时才共表，并在“调研主题/行业”和备注保留各自用途。更换电脑或宿主无持久目录时，按第3步在已登录飞书恢复原表，再登记；不要承诺未验证环境的自动识别。无Python时依相同格式读写该固定目录并回读，不退回每聊天一个绑定。

## 保留原版结构

- 已有表的字段、单选选项、顺序和视图保持不变，不为升级重建或改名；先读实际schema再映射。只在完成本次写入确实缺字段时补缺失字段，不覆盖用户自定义列。
- 首次建表采用25个原字段，定义见 `base-schema.json`；8个分类视图为：获客类、AI视频类、广告类、口播类、IP类、知识干货类、种草测评类、剧情娱乐类。每个视图仅筛选“视频类型”为对应值，保留默认全部记录视图。先查现有视图，只补缺失项。
- 表格列多不代表都要采集。没有读取到的数据留空，不填0，不为填表遍历评论、批量转写或重新设置统一点赞门槛。“命中门槛”“时间窗”和类型专属字段按本轮真实条件填写，没有对应条件就留空。
- “建议选题、适配理由、可以怎么拍、视频总时长及读取时间”放现有“备注”中，分别标明创作建议与实测事实；“内容证据”只放实际观察证据。保留已有备注，追加新用途时避免重复整段。
- 点赞等数字列仅填可确认数字；页面只显示“1.2万”等缩写时在备注保留原显示值，不伪造精确数值。发布时间不明留空；调研日期使用实际调研日期。

## 两阶段增量写入

1. 第一阶段：完成少量候选核验后，按视频ID（必要时规范链接）一次查重。新视频批量新增基本信息、类型、内容证据及本次选题建议；原文相关字段暂空。阶段一未转写不等于“无口播”。返回新增/已有条数与表链接，然后等待用户选择。落表不触发进一步搜索或ASR。
2. 第二阶段：按同一视频ID定位原行，只把完整转写写入“口播文案”，将有证据的语音时长写“口播时长(秒)”，确认有人声填“有无口播=有”。备注保留来源方式、校对状态、视频总时长与语音区间；不把视频总时长冒充口播时长。无口播需实际确认后才填“无”；提取失败写备注，原文字段留空。
3. 如果第二阶段直接收到链接且表里没有该视频，先建一行再补原文。已存在原文且与本次完整转写一致时跳过重写；发现原文不同，先保留已有内容、核对来源及人工修改，不自动覆盖人工稿。
4. 同一任务重复运行不能新增重复行。不要沿用旧版“已存在就整行跳过”而漏补口播，也不要用整行替换清空点赞、备注或用户填写的字段。只提交需要新增或补充的单元格。
5. 飞书工具可用时先读 `lark-base`，按实际schema生成CellValue。建表、建视图只在首次或缺项时做；之后批量查重、批量新增/补写，避免逐条全表扫描。远端不可访问时保留本次待写入数据，下次只续写，不重搜或重转写。
6. 写入后统一回读本批记录，核对新增/补充/跳过条数、视频ID以及“口播文案”全文。按段保留的原文不增删、不改写，不得出现字面\n、截断或摘要；明确区分机器识别原稿与已人工听校稿。返回表格及选中记录的定位信息。

独立飞书文档只在用户明确另要时创建，可把链接追加到对应行备注；表内原文仍是持续积累入口，不能只留文档链接代替完整口播。
