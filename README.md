# 通用抖音调研 Skill

让还没有选题的客户，从“行业＋内容类型”开始，找到真实视频参考，再完整提取选中视频的口播原文，供下一步AI改写使用。

**当前使用版本：2.0.0-rc.10。** [下载「通用抖音调研-V2.0」安装包](https://github.com/slbb1995/slbb-dydy-skill/releases/download/v2.0.0-rc.10/slbb-dydy-V2.0.zip) · [版本页面](https://github.com/slbb1995/slbb-dydy-skill/releases/tag/v2.0.0-rc.10)

## 一条完整路径

行业＋内容类型 → 找选题和参考并落表 → 选定一条 → 提取完整口播原文 → 补回同一张多维表格并回读 → 下一步另行AI改写。

- 第一阶段默认找3条，参考视频总时长不超过90秒。客户无需先想出题目。
- 同时考虑传播表现与业务适配，不设跨行业统一点赞门槛。
- 第一阶段不批量下载转写；第二阶段只处理选中的视频。
- 默认对话简表＋飞书多维表格持续积累：第一阶段新增参考，第二阶段补同一行原文，后续按视频ID去重追加。
- 资料、截图、字幕和任务ID保留在各自任务目录，不能混入共享Skill或跨客户复用。

## 安装

下载上方ZIP，使用宿主的Skill导入/更新功能。已有旧版时更新原技能，避免同时启用两个同类入口。

包内目录与技术标识保留 `通用抖音调研-口播文案转写`，以兼容旧安装；日常调用名称为“通用抖音调研”。

- **豆包工作**：本版本主要实测宿主，使用其实际提供的搜索、浏览器、下载和媒体工具。
- **Codex / WorkBuddy**：可使用相同Skill文件；需要宿主具备相应的抖音读取、浏览器、下载、转写能力。配置Skill文件一致不代表所有宿主的完整流程都已实测。
- 三个辅助脚本使用Python 3标准库，不需要额外Python依赖。
- Skill不自带平台登录、付费采集API或ASR服务。转写使用宿主已有能力；`mediakit-cli`仅在实际可用且接口支持时使用，不能靠复制Skill代替安装或授权。

## 第一阶段：找选题

[可复制的启动词](docs/第一阶段启动词.txt)

```text
请使用“通用抖音调研”Skill。

客户名称：【企业或品牌名称，后续保持一致】
调研对象：【行业 + 想做的内容类型】
目标客户：【选填：希望吸引谁，不清楚可结合企业资料判断】
参考数量：3条。
视频时长：90秒以内。
企业资料：【选填：飞书资料链接，或需要读取的企业资料范围】

请结合参考视频，推荐适合我们做的选题，并说明推荐理由。
先给选题和对应参考，保存到本客户的多维表格；选定后再提取口播原文。
```

交付：建议选题、真实参考链接、适配理由、拍法思路、实测视频时长。

## 第二阶段：提取口播原文

在同一对话选一条后继续：[可复制的启动词](docs/第二阶段启动词.txt)。

```text
请使用“通用抖音调研”Skill，提取口播原文。

视频链接：【抖音视频链接】
自己的产品：【产品或服务】
提取目的：保留参考原文，供下一步AI改写使用。
交付方式：只提取视频实际说出的内容，不改写、不增删，补充到本客户原有多维表格的对应视频记录，返回表格链接。
```

自己的产品和目的只作背景，不替换原视频的产品、价格或说法。保留重复、语气词和原顺序；语音识别稿与人工听校稿如实标注。无口播时直接说明，不用画面描述补成文案。

真人直拍的改写、产品补充镜头和画中画放到后续另行请求的改稿与拍摄环节，原文始终单独保留。

## 多维表格持续积累

沿用原版25个字段、默认总表和8个分类视图（获客类、AI视频类、广告类、口播类、IP类、知识干货类、种草测评类、剧情娱乐类）。已有表保持其结构与自定义内容；首次使用才创建客户专属表，后续复用项目绑定。

选题建议、适配理由和拍法写入备注；第二阶段只补同一行的口播文案、语音时长及提取状态，不重新建行。尚未读取的数据留空，保留旧字段不意味着增加采集门槛或批量转写。

客户绑定由 `scripts/base_binding.py` 保存到本机用户固定目录 `~/.local/share/slbb-dydy/bindings/`，按客户独立存储，不随安装包分发。每次新对话先读取并核验原表；首次建表或恢复旧表后立即登记。找不到本地绑定时先在飞书恢复已有客户表，不能直接新建。旧项目绑定和旧版 `.base-memory.json` 仅作为迁移线索，核对归属后复用；权限失败不自动另建表。客户名称后续保持一致。

## 三个辅助脚本

- `scripts/base_binding.py`：跨对话登记与读取客户专属表，拒绝未经明确切换的不同目标覆盖；不创建远端表，也不替代权限与客户归属核验。
- `scripts/check_candidates.py`：检查链接与视频ID、真实时长字段、观察方法和证据记录。只能检查记录规则，不能证明记录中的事实真实发生。
- `scripts/render_asr.py`：从已完成的mediakit原始字幕JSON生成TXT、SRT、逐段表与完整性记录，保持原始文字与时间戳，避免手工重抄。

参考事实、已观察画面、推断结构、自家创作建议必须分开。单帧不等于完整观看；互动数不能证明完播、转化或某种结构有效。

## 验证范围

原版25字段、8个分类视图以及原文回写已通过飞书CLI回读核验。豆包工作本地模式下，完全新对话的第二次使用已自主找回原表并新增1条（3→4），原记录保持不变，没有重复建表。

rc.10针对旧任务目录查找慢的问题加入固定绑定入口。第三次新对话从空绑定起步，已自行在飞书恢复原表并登记固定绑定；随后因豆包可用额度耗尽中断，新增记录未完成（仍为4条）。修复后的下一新对话直接读取绑定、追加及重复视频跳过，尚待恢复额度后完成验收，不能视为全部通过。脚本已验证独立进程重读、不同客户隔离及不同目标覆盖保护。

上述是本机豆包工作验证；Windows、云电脑、其他行业和其他宿主的完整运行效果未统一验证。机器转写未人工逐句听校，没有精确Token节省比例。
