# 通用抖音调研 Skill

让还没有选题的客户，从“行业＋内容类型”开始，找到真实视频参考，再把选中的方向落实成自己的拍摄脚本。

**当前使用版本：2.0.0-rc.7。** [下载 Skill ZIP](https://github.com/slbb1995/slbb-dydy-skill/releases/download/v2.0.0-rc.7/%E9%80%9A%E7%94%A8%E6%8A%96%E9%9F%B3%E8%B0%83%E7%A0%94-v2.0.0-rc.7.zip) · [版本页面](https://github.com/slbb1995/slbb-dydy-skill/releases/tag/v2.0.0-rc.7)

## 一条完整路径

行业＋内容类型 → 找选题和参考 → 选定一条 → 获取原文与观察画面 → 拆解 → 自家产品脚本与素材清单 → 保存并回读。

- 第一阶段默认找3条，参考视频总时长不超过90秒。客户无需先想出题目。
- 同时考虑传播表现与业务适配，不设跨行业统一点赞门槛。
- 第一阶段不批量下载转写；第二阶段只处理选中的视频。
- 默认在对话交付，飞书保存按需执行。
- 资料、截图、字幕和任务ID保留在各自任务目录，不能混入共享Skill或跨客户复用。

## 安装

下载上方ZIP，使用宿主的Skill导入/更新功能。已有旧版时更新原技能，避免同时启用两个同类入口。

包内目录与技术标识保留 `通用抖音调研-口播文案转写`，以兼容旧安装；日常调用名称为“通用抖音调研”。

- **豆包工作**：本版本主要实测宿主，使用其实际提供的搜索、浏览器、下载和媒体工具。
- **Codex / WorkBuddy**：可使用相同Skill文件；需要宿主具备相应的抖音读取、浏览器、下载、转写能力。配置Skill文件一致不代表所有宿主的完整流程都已实测。
- 两个辅助脚本使用Python 3标准库，不需要额外Python依赖。
- Skill不自带平台登录、付费采集API或ASR服务。转写使用宿主已有能力；`mediakit-cli`仅在实际可用且接口支持时使用，不能靠复制Skill代替安装或授权。

## 第一阶段：找选题

[可复制的启动词](docs/第一阶段启动词.txt)

```text
请使用“通用抖音调研”Skill。

调研对象：【行业 + 想做的内容类型】
目标客户：【选填：希望吸引谁，不清楚可结合企业资料判断】
参考数量：3条。
视频时长：90秒以内。
企业资料：【选填：飞书资料链接，或需要读取的企业资料范围】

请结合参考视频，推荐适合我们做的选题，并说明推荐理由。
先给选题和对应参考，选定后再深入拆解。
```

交付：建议选题、真实参考链接、适配理由、拍法思路、实测视频时长。

## 第二阶段：落实内容

在同一对话选一条后继续：[可复制的启动词](docs/第二阶段启动词.txt)。

```text
请继续使用“通用抖音调研”Skill，进入第二阶段。

选定参考：【第几条或视频链接】
落地产品：【本次准备拍的产品或服务】
内容目的：【这条内容希望达到什么效果】
交付内容：完整ASR稿、内容结构与关键镜头拆解、适合我们实际拍摄的脚本和素材清单。
保存方式：保存到本轮任务本地文件，返回路径。

复用前面的调研资料，参考内容与我们的创作建议分开；产品事实以已确认资料和实物为准。
```

视觉作品不需要原文时，将“完整ASR稿”改成“画面与镜头拆解”，跳过无用转写。

## 两个辅助脚本

- `scripts/check_candidates.py`：检查链接与视频ID、真实时长字段、观察方法和证据记录。只能检查记录规则，不能证明记录中的事实真实发生。
- `scripts/render_asr.py`：从已完成的mediakit原始字幕JSON生成TXT、SRT、逐段表与完整性记录，保持原始文字与时间戳，避免手工重抄。

参考事实、已观察画面、推断结构、自家创作建议必须分开。单帧不等于完整观看；互动数不能证明完播、转化或某种结构有效。

## 验证范围

已在豆包工作中完成真实选题调研、单条视频下载、ASR、抽帧拆解、拍摄脚本、本地保存与回读；在原任务中验证了后续修正和确定性导出。最新rc.7尚未从空白任务独立全跑，Windows、其他行业和所有宿主的运行效果未统一验证。没有精确Token节省比例。
